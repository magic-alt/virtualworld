# Unreal 本地验收改进设计

## 目的与范围

用户已经安装 Unreal Engine 5，希望直接在本机验收小王子与关节模组。
当前 main 已合并 PR #15，但仍要求手工填写 UE 5.8 路径、分别导出工程，
并自行整理编译、原生 smoke、画面与操作结果。本轮改善这一完整本地流程。

## 实施选择

沿用现有 Unreal C++ / glTFRuntime 运行时和 SceneSpec 数据契约。
采用一个验收目录内的两个独立原生项目（小王子完整三章、H-100），共享一个
无外部 npm 依赖的菜单和命令行入口。该方案直接复用现有 campaign 和导出器；
合并成一个新游戏项目会引入跨 campaign 切换语义；先搭建 Pixel Streaming
则会给本机验收增加无关的部署步骤。本轮选择桌面直接运行。

这是对既有实现的继续优化。具体工具脚本与 UI 操作由实现者依据现有工程决定；
不把这些实现选择描述为用户另行批准的产品需求。

## 约束

- 保留原 GLB、worlds、SceneSpec、package-lock 和 Unity 路径。
- Node.js 24；glTFRuntime 仍固定 0b22180d5d5d48b13457b683f4405113b6afd87b。
- 以 Windows 本机为首要路径，同时保留脚本的 macOS/Linux 分支。
- 通过 --engine、UE_ROOT、安装记录/已知安装目录发现真实引擎；读取 Build.version。
- BuildSettingsVersion.V5 的源码基线要求 UE 5.4 或更新的 5.x；这不构成各小版本编译认证。
- 生成器、doctor、假进程测试、数据检查均不能声明真实引擎通过。
- 新验收目录和证据目录拒绝覆盖，包括已有目录与符号链接；不删除旧工程或存档。
- 用户本机引擎不可从当前执行环境直接调用；最终提供可复现操作和真实结果收集方式。

## 交付

1. `npm run unreal:prepare -- --out FRESH_DIRECTORY` 生成两个原生工程、中文验收指南、
   案例清单及 `Review.cmd` / `review.mjs` 入口。
2. 原生 helper 增加环境诊断、安装发现、工程生成/编辑器打开、日志证据收集。
   菜单可直接启动沙漠、B612、地球、关节，保留底层退出码和编译日志。
3. 修复审计确认的 C++ 导入/启动/控制阻塞；补齐小王子跳跃时保留平面边界与球面径向约束。
   提供回到初始视角、暂停、重置和清楚的操作提示，便于复现验收条件。
4. 本机结果明确区分环境检查、C++ 编译、native smoke、人工画面与键盘操作、独立打包。
   人工检查从 pending 开始，收集脚本不能自动填写 pass。
5. Windows 文档明确 C++ 工具链、首次插件下载、完整路径和输出文件位置；故障表按阶段提供解决方法。

## 验收

软件侧执行原有测试、类型检查、构建、格式与新增 CLI/导出测试；实际生成两个工程并
运行数据检查和缺少引擎时的失败路径。独立代码评审检查固定插件 API 与引擎调用。
本机必须实际运行编译与 native smoke，再逐项检查三章移动/剧情/字体与关节全周旋转、
形变、传动方向、制动、剖切、爆炸、子系统隔离。结果和仍未完成项进入 PR 与文档。
