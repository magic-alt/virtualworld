# UE5 单模组 STP 导入

## 目标与范围

在 Windows UE5 关节展示 GUI 内选择本地 `.stp` / `.step` 文件，导入其他模组。画面与操作面板始终对应一个当前模组；一个 STEP 装配中的多个零件仍属于同一个模组。保留默认 H-100 的演示能力，提供恢复默认模组入口。

普通 STEP 只提供静态观察，不推断传动、剖切、抱闸或工程确认参数。保留可用名称、层级、颜色和实际尺寸，自动居中适配视角，不把模型归一化为固定尺寸。

## 方案比较与选择

用户已选择：直接在 UE5 GUI 内导入。另一方案是在网页 Studio 导入后重新导出 UE5；该方案能复用现有流程，但每次换模型都需重新导出，不符合本次选择。

实现建议沿用已固定版本的 OCCT STEP 解析器，在本机独立转换进程内生成 GLB，再复用 glTFRuntime 显示。相比新增原生 CAD SDK，这能复用已有单位和颜色转换规则，减少新的 SDK 与二进制依赖；代价是运行机器需要 Node.js 24 和随工程准备的转换依赖。准备、诊断和打包说明必须明确这一要求，不能依赖仓库路径或网页服务。

## 用户操作

关节面板新增“导入 STEP”和“恢复 H-100”。文件选择器只允许选择一个文件。取消不改变当前模组；转换期间显示状态并禁止重复提交。成功后整体替换当前模组，清除旧运动、隐藏、隔离和爆炸状态；普通 STEP 面板只显示观察与导入相关操作。恢复 H-100 时恢复其原有机构控件。

## 数据与资源

原始 STEP、转换 GLB 和校验记录分开保存到工程 Saved 下独立导入目录，不修改默认资源。导入生成合法 SceneSpec，复用校验、原子 SceneCommands 和引擎导出契约；不能通过导入另建一套持久化场景定义。网格路径来自最终序列化 GLB，输出使用米、Y-up，再由现有适配器转成 UE 坐标。

转换、校验和候选模型加载全部成功前，原模组保持可见；候选模型在提交前不可见。失败只显示可恢复错误，不清空原场景。切换场景、恢复默认或退出时取消任务并递增导入代次；过期结果不可提交。替换后释放旧 Actor、网格、材质与加载缓存。

## 边界与验证

限制输入大小、转换时长和输出复杂度；拒绝空文件、损坏 STEP、无有效可见几何及非法输出。路径通过进程参数传递，不拼接 shell 命令；不使用网络、模型服务或密钥。转换依赖按现有固定版本准备并保留第三方许可。

验证使用真实毫米立方体和多零件 STEP 装配，检查实际尺寸、可见几何、层级与颜色；覆盖 A→B、失败保留 A、取消、恢复默认及过期结果。执行仓库要求的单元、类型、构建、浏览器、格式和依赖检查；真实 UE 编译、运行时导入及桌面打包须单独记录，不用源码断言冒充原生验收。

## 待实施时确定

Windows 文件选择器、转换依赖准备方式和候选资源暂存的具体接口由实现阶段结合现有运行器确定。若发现无法支持独立桌面运行，应先说明限制再调整设计。
